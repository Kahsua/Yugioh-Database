# Kartenarchiv – Projektkontext für Claude Code

Yu-Gi-Oh-Sammlungs-App (Deutsch) für Alex + 2–3 Freunde. Vanilla JS/HTML/CSS, **kein Build-Schritt**,
gehostet auf GitHub Pages (`kahsua.github.io/Yugioh-Database/`), PWA (Android-Chrome), Backend Supabase.

## Dateien
- `index.html` – alle Views + Modals; bindet `style.css?v=N` und `app.js?v=N` ein
- `app.js` – gesamte Logik (Auth, Suche, Sammlung, Verlauf, Import, Reparatur, Scan/OCR, Zurück-Taste)
- `style.css` – dunkles "Duell-Archiv"-Theme, Mobile-Regeln
- `config.js` – Supabase-URL (ohne `/rest/v1/`) + anon-Key (öffentlich ok). **Alex' echte Werte nicht überschreiben.**
- `supabase-schema.sql` – idempotent, Tabellen profiles/cards/history, RLS, Trigger `handle_new_user`, Migrationen
- `service-worker.js`, `manifest.json`, `icons/` – PWA
- `Yugioh_Sammlung_Import.csv` – Altbestand (Import-Vorlage)

## Regeln
1. **Cache-Busting:** Bei JEDER Änderung an `app.js`/`style.css` die `?v=` in `index.html` hochzählen
   (aktuell app.js v15, style.css v6) und bei Shell-Änderungen `CACHE_NAME` in `service-worker.js` erhöhen.
2. Supabase-Client heißt `supabaseClient` (nie `supabase` – Namenskonflikt mit dem CDN-Global).
3. Nie den `service_role`-Key ins Frontend. Sicherheit läuft über RLS.
4. Listen >1000 Zeilen nur über `fetchAllRows` (`.range()`) mit `.order("created_at").order("id")`.
5. `overflow-x:hidden` NICHT auf html/body setzen (zerstört Scrollen); nur auf `.view`.
6. Dubletten-Schutz beim Speichern: erst `ygo_id`, dann Namens-Fallback; UPDATE addiert die Anzahl.
7. Android-Zurück-Taste läuft über History-API (`pushModalHistory`/`closeOpenModal`/`popstate`).
8. Sprache der UI und Antworten an Alex: Deutsch.

## Externe APIs
- YGOPRODeck v7 `cardinfo.php` (fname/id/archetype, `language=de`), `archetypes.php`; max. 20 Req/s.
- Tesseract.js (eng+deu) für den Kartenscan, Levenshtein-Fuzzy-Matching gegen die Kartenliste.

## Betrieb / Backup
- `.github/workflows/keepalive.yml` pingt Supabase alle 3 Tage (gegen Pause nach 7 Tagen Inaktivität).
- `.github/workflows/backup.yml` exportiert montags profiles/cards/history (JSON+CSV), verschlüsselt sie
  (`scripts/backup-crypt.mjs`, Secret `BACKUP_PASSWORD`) und legt sie als Workflow-Download ab (90 Tage).
  Ins Repo kommt NUR `backup/last-backup.json` – hält das Repo aktiv (GitHub deaktiviert Cron-Workflows
  nach 60 Tagen ohne Commit). **Backup-Daten nie ins öffentliche Repo committen** (`.gitignore`).
- Lokales Backup: `node scripts/backup.mjs` (schreibt nach `backup/`).
- Download entschlüsseln: `node scripts/backup-crypt.mjs decrypt backup-JJJJ-MM-TT.enc wiederhergestellt`
  (Passwort aus `backup-passwort.txt`, lokal, nicht im Repo).
- Secrets im Repo: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `BACKUP_PASSWORD`.
- Benutzerkonten (auth.users) sind NICHT im Backup. `gh` CLI ist installiert und als Kahsua angemeldet.
- Vor eigenem `git push` erst `git pull --rebase` (der Backup-Bot committet wöchentlich).

## Deployment
`git push` auf `main` → GitHub Pages baut automatisch (1–2 Min). Danach in der App 🔄 drücken.
